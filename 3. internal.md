# Git Internals: Hashes, Objects, and Data Storage

## Different Hashes

My latest Git commit hash was: `5ba786fcc93e8092831c01e71444b9baa2228a4f`.

Even with identical content, commit hashes can differ between repositories due to factors such as the commit message, author's name and email, date and time, and parent commit hashes. Consequently, hashes are practically unique. While SHA-1 collisions are theoretically possible, they are highly improbable in typical usage.

**Note:** Hash = SHA. Git uses the SHA-1 cryptographic hash function for commit hashes.

## The Plumbing

Let's explore some of Git's "plumbing" commands.

### It's Just Files All the Way Down

All data within a Git repository resides in the hidden `.git` directory, encompassing commits, branches, tags, and other objects. These objects are stored in the `.git/objects` directory, and a commit is a specific type of object.

4.  Use `ls -al` within that directory to list its contents. You should find a file whose name consists of the remaining characters of your commit hash. Provide the full path to this object file.

#### Cat File

Git provides a plumbing command, `cat-file`, to view commit contents without directly manipulating object files.

```bash
git cat-file -p <hash>
```

**Assignment:**

1.  Use `git cat-file -p <hash>` to view the contents of your last commit.
2.  Redirect the output to a temporary file for CLI testing:
    ```bash
    git cat-file -p <hash> > /tmp/catfileout.txt
    ```

**Tip:** Use `git log -1` to get the hash of your last commit.

### Trees and Blobs

Git uses specific terms for its data structures:

*   **tree:** Represents a directory.
*   **blob:** Represents a file.

Example inspection of a commit:

```
> git cat-file -p 5ba786fcc93e8092831c01e71444b9baa2228a4f
tree 4e507fdc6d9044ccd8a4a3061324c9f711c4667d
author tsp <tsp@gmail.com> 1705891256 -0700
committer tsp <tsp@gmail.com> 1705891256 -0700

A: add contents.md
```

This output shows the tree object, author, committer, and commit message. The file content itself is stored in a blob object.

**Assignment:**

1.  Use `git cat-file -p` with the hash of the tree object from your last commit. You should see a blob object with its own hash.
2.  Use `cat-file` with the blob object's hash to view its contents.
3.  Redirect this output to a temporary file: `/tmp/blobfile.txt`.

## Storing Data

Git stores an entire snapshot of files at each commit level, not just the changes made in that commit.

### Optimization

While Git stores full snapshots, it employs optimizations to manage `.git` directory size:

*   Files are compressed and packed for efficient storage.
*   Identical files across different commits are deduplicated; unchanged files are stored only once.
