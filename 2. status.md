# Git File Status

In a Git repository, files can exist in several states. Key states include:

*   **Untracked:** Files that Git is not currently monitoring.
*   **Staged:** Files marked for inclusion in the upcoming commit.
*   **Committed:** Files that have been saved to the repository's history.

The `git status` command provides an overview of your repository's current state, indicating which files are untracked, staged, or committed.

# Staging Files in Git

The `contents.md` file you created is currently untracked. To include it in the next commit, you need to stage it using the `git add` command. This process adds the file to Git's "index."

Files are only included in a commit if they have been explicitly staged using `git add`.

The command to stage files is:

```bash
git add <path-to-file | pattern>
```

For instance, to stage a file named `i-use-arch.btw`, you would run:

```bash
git add pich.nice
```

# Committing Changes in Git

Once a file has been staged, you can commit it. A commit represents a snapshot of your repository at a specific moment in time, effectively saving the repository's state and enabling Git to track project changes. Each commit is accompanied by a message that describes the modifications made.

To commit all staged files, use the following command:

```bash
git commit -m "your message here"
```

## Assignment: Commit `contents.md`

    ```bash

    ```
    *Note: Typically, commit messages do not start with "A:". This prefix is used in this course for easy identification of commits.*

## Tip: Amending Commit Messages

If you need to change the last commit message, you can use the `--amend` flag:

```bash
# Change the last commit message
git commit --amend -m "A: add contents.md"
```

# Git Log

A Git repository is essentially a list of commits, with each commit capturing the complete state of the repository at a specific moment. The `git log` command displays this commit history, which is fundamental to Git's function as a version control system. It allows you to see:

*   Who made a commit
*   When the commit was made
*   What was changed

## Commit Hash

Every commit is assigned a unique identifier known as a "commit hash." This is a lengthy string of characters that uniquely identifies each commit. For example:

`5ba786fcc93e8092831c01e71444b9baa2228a4f`

For convenience, you can reference any commit using the first seven characters of its hash. For the example above, this would be `5ba786f`.
