## Exploring the Official Git Manual

To access the official Git manual, you can use the following command in your terminal:

```bash
man git
```

## Manual Navigation Shortcuts

Here are some essential shortcuts for navigating the manual:

*   `q`: Quits the manual
*   `j`: Moves down one line
*   `k`: Moves up one line
*   `d`: Scrolls down half a page
*   `u`: Scrolls up half a page
*   `/<term>`: Searches for the specified `term`
*   `n`: Moves to the next search result
*   `N`: Moves to the previous search result

# Porcelain and Plumbing in Git

Git commands are categorized into two types: high-level ("porcelain") commands and low-level ("plumbing") commands.

## Porcelain Commands

Porcelain commands are those that developers interact with most frequently. Examples include:

*   `git status`
*   `git add`
*   `git commit`
*   `git push`
*   `git pull`
*   `git log`

## Plumbing Commands

Plumbing commands are typically used less often by developers. Some examples are:

*   `git apply`
*   `git commit-tree`
*   `git hash-object`

The focus for developers is primarily on the high-level commands, though low-level commands may be explored occasionally for a deeper understanding of Git's inner workings.

# Quick Git Configuration

To properly track code changes and attribute them to the correct individuals, Git requires your user information. This ensures you receive credit or are identified for modifications made to the codebase.

Git offers configuration settings at both the global and repository levels. Typically, the global configuration is sufficient for most users.

## Setting Your Identity

Before you begin making commits, you need to configure your username and email address. Check if these are already set by running:

```bash
git config get user.name
git config get user.email
```

If these values are not set, you can configure them using the `git config set` command. It's recommended to use your GitHub username and email address:

```bash
git config set --global user.name "your_github_username"
git config set --global user.email "your_email@example.com"
```

## Setting the Default Branch

To ensure consistency, let's set a default branch for new repositories. Run the following command:

```bash
git config set --global init.defaultBranch master
```

We are using `master` as the default for now, as it is Git's default. This will be revisited later to change to `main`, which is GitHub's current default.

## Verifying Your Configuration

Your global Git configuration settings are stored in the `~/.gitconfig` file. You can view its contents by running:

```bash
cat ~/.gitconfig
```

# Git Repositories: Initialization

The initial step in any project is to establish a Git repository. A Git "repository" (or "repo") is the fundamental unit for managing a project, with generally one repository dedicated to each distinct project.

A repository is essentially a directory housing your project's files and subdirectories. Its distinguishing feature is the presence of a hidden `.git` directory. This hidden directory is where Git meticulously stores all its internal tracking and versioning data for the project.

## Cspotify Project

For this course, we will be managing content for "Cspotify," a conceptual self-hosted music streaming application. Cspotify will serve its content directly from a Git repository.

## Assignment: Initialize a Cspotify Repository

1.  **Navigate to your desired project storage location** on your filesystem.
2.  **Create a new directory named `cspotify`** and change into it:
    ```bash
    mkdir cspotify
    cd cspotify
    ```
3.  **Initialize a new Git repository** within the `cspotify` directory:
    ```bash
    git init
    ```

You should now find a hidden `.git` directory within your `cspotify` directory, confirming the successful creation of a new Git repository. You can verify this by listing the directory's contents, including hidden files:

```bash
ls -a
```
